# 如何看懂项目

作为一名刚实习不久的实习生，在刚接受公司的项目的时候，被庞大而复杂的项目文件带的眼花缭乱，不知道从哪里下手，或者在修改文件的时候会不小心牵连到其他的文件。

所以对于广大的实习生以及刚入职的程序员来说，快速地看懂项目文件是一个必会的技能。

我会分享在实习的这段时间中所积累的“读项目”心得，希望能够帮到你。

## 刚拿到新项目，该怎么办？

在刚拿到一个新项目的时候，第一件事是需要知道这个项目是用什么架构搭建出来的，就前端而言，你得知道这个项目是React，Vue，或者NextJS 等。然后去对应的架构官网去看文档中定义的项目结构是什么样子的。这里我以NextJS为例：

官方文档：[https://nextjs.org/docs/app/getting-started/project-structure](https://nextjs.org/docs/app/getting-started/project-structure)

官方给出了具体的NextJS项目应该长什么样子：

```markdown
my-nextjs-app/
├─ app/                          
│  ├─ layout.tsx                
│  ├─ page.tsx                 
│  ├─ dashboard/               
│  │  ├─ layout.tsx              
│  │  ├─ page.tsx                
│  │  ├─ settings/
│  │  │  └─ page.tsx          
│  ├─ api/                 
│  │  ├─ auth/
│  │  │  └─ route.ts          
│  │  ├─ posts/
│  │     └─ route.ts                          
│  ├─ not-found.tsx            
│  ├─ error.tsx              
│  └─ loading.tsx             
|
├─ components/                  
│  ├─ ui/                   
│  ├─ layout/                    
│  ├─ forms/                    
│  └─ charts/                   
|
├─ lib/                       
|
├─ hooks/                       
|
├─ store/                        
│  └─ useAppStore.ts
|
├─ public/                  
│  ├─ images/
│  │  ├─ logo.png
│  │  └─ banner.jpg
│  └─ favicon.ico
|
├─ types/                        
│  ├─ user.ts
│  ├─ post.ts
│  └─ index.d.ts
|
├─ next.config.mjs           
├─ tailwind.config.ts           
├─ tsconfig.json                
├─ package.json
└─ README.md

```

该项目中有app，components，lib，hooks，store，public，types以及配置文件。如果你们公司的项目使用的是NextJS 15 App Router架构的话，那么大概率项目结构就长这个样子。

- app
    
    这是存放具体页面以及后端接口的文件，可以在这里编写网页中不同的页面以及编写后端接口
    
- components
    
    这个文件夹下存放的是具体的组件，你可以将按钮组件，卡片组件等统一存放在这里，然后在编写页面的时候调用这些组件
    
- lib
    
    这是存放具体工具或者服务模块的地方，可以在这里封装API请求，编写日期，格式化工具等
    
- hooks
    
    这个文件夹下是自定义的React Hooks，存放自己编写的钩子函数
    
- store
    
    该文件一般会在大型项目中使用，用来进行复杂的状态管理
    
- public
    
    这个文件夹下会存放一些静态文件，比如网页的logo，一些图片等
    
- types
    
    这个文件中会存放类型定义，一般在大项目中需要定义User的类型或者其他数据类型时会使用
    
- 其余的文件大多为配置文件，比如tsconfig，tailwind.config等，来进行工具或者打包模式的配置等，在项目初始化的时候就会把这些文件配置好，所以一般不会去改这些文件

当了解了这些文件的作用是干什么的时候，在接手新项目时，脑海中就会有一个大体的框架，寻找活修改某些东西的时候也就知道去哪里操作。

当今大多数项目都会遵循命名规范，将每个文件的作用，是什么都已经命名好了，单看文件名称也能够略知一二，知道这个文件是干什么的，所以在编写新文件的时候也要遵循一定的命名规范，不可随意命名。

## 函数太多，看不过来？

当了解了具体的项目结构后，就该看具体的代码了。打开一个项目后发现各种各样的函数扑面而来，甚至一个函数一两百行，一个文件中几十个函数。这要一行一行去看，光是看项目就得一两周，更别提去修改了。

其实这些函数也会有自己的命名规范，每个函数干什么用的，一眼就能看出来。

在React中，基本会有以下几类函数：

- 组件函数
    
    React中最基本的单位，一般返回JSX，用来渲染UI
    
- 事件处理函数
    
    大多以handle开头，一般是在用户点击某个按钮，提交表单的时候会调用此函数
    
- 状态更新函数
    
    该函数会以set开头，用来更新数据的状态，出发重新渲染
    
- 数据请求函数
    
    该类型函数会以fetch/get开头，用来调用API接口，请求数据
    
- 生命周期相关的函数
    
    这种函数会在useEffect()内定义，在组件初次渲染，更新或者卸载的时候进行调用
    

当然还可能会有一些内置的hooks，都会以use开头，具体的函数使用还得去hooks文件下进行查阅。

当你了解了这些函数的具体作用的时候，再阅读析项目时，看到handle开头的函数，就知道这是用户交互后要做什么事情；看到set开头的函数时，就知道这是要更新数据了；看到fetch/get开头的函数时，就知道要向接口请求某些数据了。。。也就不会面对几十个函数无从下手

## 看项目的终极奥秘：扒洋葱

分析新项目的时候，把项目当作洋葱一样，先从最大的文件结构（最外面一层）开始分析，到每个文件当中的不同函数（里面的一层），再具体到每个函数中有什么逻辑（最内层）

这样一层一层扒开，分析每一层的作用，你也就会对项目有清晰的认知，知道每个函数，每个文件都是干什么的。

我建议在每次点开一个文件夹的时候，先把所有的函数都折叠起来（VScode中有代码折叠的功能，左侧有小箭头），只看每个函数的名称，具体的逻辑不要去管，看看这个项目中具体有什么函数，先构建起一个大体的框架；然后再一个一个展开函数，深扒具体的细节，慢慢填充细节。等熟练之后，快速看懂项目，上手修改也就不言而喻了。
